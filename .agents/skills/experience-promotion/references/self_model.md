# Self-Model

Use this reference only when evidence may change the agent's current operational capability or constraint model.

The Self-Model is not an autobiography, identity narrative, or timeless truth. It is a dated operational model that can become stale.

## Eligible Content

- available and unavailable capabilities;
- available Skills and tools;
- model or environment restrictions;
- resource constraints;
- observed failure modes;
- actions requiring a human;
- environment assumptions.

Prefer claims traceable to documentation, verified environment state, direct observation, repeated observation, or an explicit human report. Label the evidence source and confidence when the claim is material. Distinguish verified constraints from provisional explanations.

Use [../assets/SELF_MODEL.template.md](../assets/SELF_MODEL.template.md) when creating a new mutable record.

## Update Rules

- Update only the affected section; do not rewrite the full file for one observation.
- Include a last-verified date or timestamp.
- Mark environment-specific or model-specific scope.
- Downgrade, supersede, or remove stale claims after verification; preserve important provenance in an episode or archive when needed.
- Do not generalize one failed attempt into a permanent capability limit.
- Do not load the Self-Model for unrelated tasks.

If an unresolved capability issue needs tracking rather than a settled model update, use [../assets/ISSUES.template.md](../assets/ISSUES.template.md).
