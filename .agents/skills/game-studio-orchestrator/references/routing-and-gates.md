# Routing and Gates

## Route by the Current Decision

| Current uncertainty | Route |
|---|---|
| Why this game should exist; creator identity or pride | `game-creative-director` |
| Lineage, comparable weakness, transformation, derivative risk | `game-reference-originality` |
| Player fantasy, thesis, pillars, return or memory reason | `game-concept-design` |
| Loop, decision quality, depth, mastery, system alternatives | `game-systems-design` |
| What to test next and at what fidelity | `game-prototype-strategy` |
| Build the bounded local experiment | `game-implementation` plus `local-first-app-development` |
| Judge a frozen concept or build | `game-evaluation` |
| Choose mutation, ablation, kill, or promotion | `game-iteration` |

Use `research` for literature-sensitive, historical, scientific, or defensible
novelty claims. Use current web research for market, new releases, or changing
competition. Do not load a specialist merely because it exists.

## State

Ambition: `experiment`, `prototype`, `small_game`, `release_candidate`, or
`signature_candidate`.

Prototype rung: `D0`, `P0`, `P1`, `P2`, `VS`, `A0`, or `RC`.

Gate decision: `advance`, `hold`, `mutate`, `kill`, or `de_scope`.

## Promotion Gates

Production promotion requires all of:

- a runnable core at `E2` or stronger;
- creator playtest evidence at `E3` for the intended core fun;
- explicit creator conviction with unresolved concerns visible;
- design coherence between intent, mechanics, feedback, and consequences;
- a current bottleneck and a reversible next production plan.

`signature_candidate` additionally requires:

- a distinct identity and an answer to `Why this game, not merely this genre?`;
- at least one demonstrated strongest or signature moment;
- reference differentiation expressed as transformation, not feature mixing;
- creator pride after hands-on play;
- external human evidence at `E4` or `E5` for human-dominant claims.

These are necessary review conditions, not proof of masterpiece status.

## Hard Holds

Hold or kill when any applicable condition remains unresolved:

- no player action connects the fun claim to an observable signal;
- implementation scope is growing while the core question is unanswered;
- evaluation is self-authored praise with no preserved observations;
- automation is being used to claim fun, fear, wonder, beauty, or memorability;
- `A + B` is presented as originality without a new interaction or experience;
- polish, lore, rewards, randomness, statistics, or tutorial volume compensates
  for a weak loop;
- a consequential identity fork lacks creator choice.

## Anti-Pattern Vocabulary

Use these exact identifiers when useful:

`feature_inflation`, `content_brute_force`, `lore_dump`, `stat_difficulty`,
`randomness_as_depth`, `reward_dependency`, `tutorial_compensation`,
`theme_skin`, `frankenstein_design`, `premature_polish`,
`premature_convergence`, `self_evaluation_bias`, `creator_overfitting`,
`market_overfitting`, `survivorship_bias`, `competent_but_generic`, and
`fast_v0_slow_v1`.
