# Lineage and Transformation

## Reference Ledger Method

For each selected source record:

1. relevance to the current design question;
2. `why_it_works` with evidence or clearly labeled inference;
3. essential versus genre-specific elements;
4. what would break the source design;
5. a transferable principle;
6. the changed constraint in the new game;
7. the resulting interaction, behavior, and intended experience;
8. inherited and transformed elements;
9. derivative risk and mitigation;
10. source provenance and access date when researched externally.

Use the same structure for cross-domain sources. Borrow causal structure, not
surface vocabulary or theme.

## Comparison Set

Prefer a small set with different functions:

- closest mechanical ancestor;
- strongest competitor or benchmark;
- anti-reference showing a failure boundary;
- cross-domain source when it introduces a useful structure;
- disconfirming example that challenges the proposed principle.

Do not create a canon whose features are all mixed into one game.

## Stop Rule

Stop when new sources repeat known principles, the main derivative risk is
understood, and the next uncertainty is empirical. Report `not found within
this search` rather than `does not exist` unless the stronger claim is proven.
