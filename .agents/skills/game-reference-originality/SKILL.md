# Game Reference Originality

## Trigger

Use when comparable awareness, lineage, differentiation, or cross-domain
inspiration can change a concept or prototype decision. For freshness-sensitive
works, browse current primary or authoritative sources. Use the `research` Skill
for scholarly or novelty claims requiring its evidence protocol.

## Inputs

Start from the creative intent, fun hypothesis, target experience, declared
references, anti-references, and comparison boundary. Define the minimum search
needed and a stop condition before broad research.

## Workflow

1. Select references that expose the design's strength or weakness, not just
   favorites or sales leaders.
2. For each, extract `why_it_works`, then a `transferable_principle`; do not copy
   a surface feature.
3. Record `source mechanic -> underlying principle -> changed constraint -> new
   interaction -> intended player experience`.
4. Audit inherited elements, transformed elements, new relationships, new player
   behaviors, new experiences, and derivative risk.
5. Include relevant anti-references and, when useful, structures from outside
   games. Translate structure, not decorative theme.
6. State whether originality is observed, inferred, hypothetical, or still
   unverified. `A + B` is not enough unless the interaction produces `C`.

## Outputs

Update `reference-ledger.yaml` and a concise differentiation statement. Use
[lineage-and-transformation.md](references/lineage-and-transformation.md) for
the comparison method and stopping rules.

## Stop Conditions

Stop when additional references are redundant and the next uncertainty belongs
to design or play. If derivative risk remains material, hold the concept or
design a discriminating transformation test; do not conceal it with theme.
